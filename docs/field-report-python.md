# Field report: docrot on seven Python projects

Date: 2026-09-23. Binary: `docrot 0.2.0` for the first five projects
(later sections say which version they used), default `.docrot.json`, git
enabled, shallow clones from GitHub. The projects were chosen for size and
for how they write documentation: MkDocs sites with heavy `{* include *}`
snippets (FastAPI, Typer), API pages generated by mkdocstrings (Pydantic),
plain Markdown (httpx, Starlette), and — from 0.4.0 — Sphinx sources
(requests, Django). Two of them keep translations.

## Numbers

| project | .py files | lines of Python | docs | references | errors | warnings | info | time |
|---|---|---|---|---|---|---|---|---|
| httpx | 60 | 17,753 | 26 | 661 | 21 | 1 | 94 | 0.2 s |
| starlette | 84 | 21,690 | 30 | 812 | 2 | 1 | 30 | 0.2 s |
| typer | 637 | 35,622 | 80 | 2,555 | 1 | 2 | 101 | 1.0 s |
| pydantic | 453 | 177,528 | 99 | 4,354 | 23 | 3 | 52 | 0.9 s |
| fastapi | 1,138 | 112,998 | 1,692 | 27,887 | 184 | 148 | 1,895 | 16 s |

FastAPI is the stress case: 1,692 Markdown files (the English docs plus
twenty translations), 372 source/translation pairs detected automatically
from the `docs/en/docs/…` ↔ `docs/<lang>/docs/…` layout, and one `git blame`
per document. Nothing crashed and no project needed configuration.

## What it found (verified by hand)

**Removed API still in the migration guide.** Pydantic `docs/migration.md`
names `pydantic.NoneStr`, `pydantic.NoneBytes`, `pydantic.NoneStrBytes`,
`pydantic.typing.AbstractSetIntStr` and `pydantic.json.ENCODERS_BY_TYPE`;
none exist in the current tree (they are what the guide tells you to stop
using, but the guide never says they are gone). docrot's did-you-mean points
at `pydantic.types.constr` / `conbytes`, the closest surviving names.

**Anchors that no heading defines.** httpx `docs/advanced/clients.md` links
to `#client-instances` and `#merging-of-parameters`; the headings are "Usage"
and "Merging of configuration". `docs/advanced/proxies.md` links to
`#routing`; there is no such heading. Pydantic `docs/migration.md` links to
`concepts/pydantic_settings.md#customise-settings-sources`, which does not
exist.

**Documentation that moved without its links.** FastAPI
`docs/en/docs/release-notes.md` still links to `docs/tutorial/body.md`,
`docs/async.md`, `docs/features.md` and other pre-reorganisation paths; the
files now live under `docs/en/docs/`. Twelve translations of
`deployment/versions.md` link to `../release-notes.md`, which only the
English tree has.

**Translations that drifted.** Across FastAPI's Japanese, Korean and Chinese
trees docrot reports 51 code blocks that differ from the English source
(`docs/ja/docs/async.md` blocks 5–7, `docs/ja/docs/deployment/docker.md`
Dockerfiles). Code is expected to be identical across translations, so each
of these is either a stale translation or an untranslated edit.

**Historical documents, correctly historical.** httpx `CHANGELOG.md` names
`httpx.PoolLimits`, `httpx.HTTPProxy`, `httpx.StatusCodes` — all removed in
the versions the entries describe. These are true statements about the past.
docrot reports them because a changelog is still a document; the sensible
setting for such files is `"exclude": ["CHANGELOG.md", "HISTORY.md"]` or a
`<!-- docrot:ignore-file -->` at the top.

## What Python taught the heuristics

The first run on FastAPI reported 1,614 errors and 6,102 warnings; the
final one reports 184 and 148. Every change is in `internal/extract`,
`internal/resolve`, `internal/index/py` or `internal/index/anchors` and has
a test.

| Symptom | Fix |
|---|---|
| `fastapi.responses`, `starlette.routing`, `pydantic.v1` reported as missing symbols | a module or package name is a valid reference |
| `fastapi.status`, `fastapi.FastAPI` reported as missing (defined elsewhere, re-exported) | top-level `import` / `from … import` statements bind names in the importing module; `pkg.Name` also matches a declaration in any submodule of `pkg` |
| `typing.Annotated`, `datetime.strptime()`, `enum.Enum` reported as missing | a dotted name starting with a standard-library module is skipped unless the repository defines that module itself |
| `app.add_middleware()`, `app.routes`, `client.get()` reported as missing (the docs' example objects) | receiver-like first parts (`app`, `client`, `request`, `self`, …) are skipped |
| `app.main`, `app.routers.items` reported as errors (tutorial layouts under `docs_src/`) | symbols defined under `tests/`, `docs/`, `docs_src/`, `examples/`, `scripts/` are weaker claims → info |
| 5,954 warnings for `../../docs_src/x.py` includes written from MkDocs' `docs_dir` | a `../` path that fails from the document's directory is retried from each ancestor directory |
| `## In a hurry? { #in-a-hurry }` anchors reported broken; `[](){#pattern-constraint-note}` anchors reported broken | Markdown-extensions custom ids (`{ #id }`, standalone `{#id}`, inline attr lists) are indexed as anchors |
| `api/config.md#pydantic.config.configdict.frozen` reported broken (page generated by mkdocstrings) | a document containing a `::: module` directive accepts any anchor |
| `#using-json_schema_extra` reported broken | slugs keep underscores, as GitHub does |
| `client.pem`, `CITATION.cff` classified as symbols | `.pem`, `.crt`, `.key`, `.cff`, `.whl`, … are file extensions |
| Japanese README links to `https://fastapi.tiangolo.com/ja/…` reported as drift against `…/…` | a leading language path segment is ignored when comparing pair links |

## What is still noisy

- `fastapi.entryPoint` (a VS Code setting) and `fastapi.temp_pydantic_v1_params`
  (an environment-ish knob) are reported once per translation: thirteen
  identical errors from one sentence. A `--dedupe-pairs` option that reports
  a translation-only finding once is the obvious next step.
- Docs that describe a project layout the reader is supposed to create
  (`app/main.py`, `templates/item.html`, `./src/client`) are warnings. They
  are not wrong, just not about this repository; `docrot:ignore` is the
  honest answer today.
- Pair link comparison reports `link only in source` for links the
  translator legitimately localised (`https://…/benchmarks/` vs
  `https://…/ja/benchmarks/` is now handled; fully different targets are
  not, and should not be).

## Code comments (`docrot comments`, full sweep of exported declarations)

| project | declarations | stale-comment | comment-mentions-missing | time |
|---|---|---|---|---|
| httpx | 339 | 0 (shallow clone) | 0 | 3.5 s |
| starlette | 385 | 0 (shallow clone) | 1 | 5.7 s |
| typer | 445 | 0 (shallow clone) | 4 | 3.3 s |
| pydantic | 3,835 | 0 (shallow clone) | 22 | 25 s |
| fastapi | 347 | 0 (shallow clone) | 2 | 14 s |

`stale-comment` needs history; the clones are `--depth 1`, so every line
has the same commit and nothing can be newer than anything. The unit test
covers the Python path with a real three-commit repository.

Verified hit: `pydantic/v1/generics.py:252` — the docstring of
`replace_types` says "`typevar_map` keys recursively replaced"; the
parameter has been `type_map` since the signature was last touched.
Plausible hits: Typer's `callback` docstring names `--install-completion`,
which no `typer.Option` in the tree declares by that literal; Pydantic's
`TypedDictExtraConfigWarning` names `extra_items`, which appears nowhere.
Noise that remains: `SimpleCookie.load` (a stdlib method cited by class
name), `TaggedUnion` (a pydantic-core type), `app/main.py` (an illustrative
layout in FastAPI's `frontend()` docstring).

What Python docstrings taught the check: FastAPI writes parameter docs as
`Annotated[..., Doc("""…""")]` *inside the signature*, so the signature
scanner has to understand multi-line triple-quoted strings; doctest and
example blocks (`>>>`, fenced code, `x = …`) inside docstrings are not
claims and are skipped; JSON-schema vocabulary (`anyOf`, `additionalProperties`)
and HTTP words (`GET`, `Cookie`) are not identifiers.

## 0.3.0 update

Same clones, `docrot 0.3.0`, git enabled.

| project | docs | references | errors | warnings | info | time |
|---|---|---|---|---|---|---|
| httpx | 26 | 691 | 21 | 1 | 94 | 0.3 s |
| starlette | 30 | 821 | 2 | 1 | 29 | 0.2 s |
| typer | 80 | 2,569 | 1 | 2 | 101 | 0.9 s |
| pydantic | 99 | 4,394 | 23 | 6 | 53 | 1.2 s |
| fastapi | 1,692 | 30,005 | 184 | 150 | 1,902 | 15 s |

- **Routes.** FastAPI's tutorials register 659 routes across `docs_src`
  (decorators with the path on the next line, `APIRouter(prefix=…)`,
  `include_router`); every route the English docs and their translations
  name resolves, including `/users/{user_id}` against `/users/{user_id}`
  in one module and `/users/me` in another. Starlette registers 106 routes
  in its tests and docs; no claim is missing.
- **Toolchain.** Release notes say "drop Python 3.8" a dozen times per
  project; they are history and are now excluded by default. What remains
  is info: FastAPI's Pydantic migration guide discusses Python 3.14
  behaviour, and Pydantic's standard-library page mentions 3.15.
- **Targets.** pydantic-core's README runs `make build-dev` against its
  own `pydantic-core/Makefile`; a document inside a directory with its own
  runner file is left alone rather than checked against the root one.
- **Speed.** The 0.2.0 numbers hid a quadratic string conversion in the
  Python signature scanner: pydantic went from 22 s to 0.5 s without git,
  FastAPI from 8.3 s to 2.3 s. With git, FastAPI's 15 s is the 1,692
  `git blame` calls; `docrot check --changed` on a clean tree takes 0.5 s.

## 0.4.0 update: reStructuredText

Two Sphinx projects joined the corpus: requests (21 `.rst` pages) and
Django (686 `.txt` pages under `docs/`, included with
`"docs": ["docs/**/*.txt", "**/*.rst", "**/*.md"]`).

| project | pages | references | errors | warnings | info | time (no git) |
|---|---|---|---|---|---|---|
| requests | 21 | 423 | 1 | 5 | 11 | 0.06 s |
| django | 686 | 16,767 | 387 | 221 | 1,112 | 4.5 s |

- **requests.** The one error is `requests.async` in `HISTORY.md`, a module
  removed years ago (true history). `:attr:` references such as
  `requests.Response.raw` — instance attributes set in `__init__` — resolve
  because the owner is a known class. `docs/community/faq.rst` says "Python
  2.7" in a sentence about SNI; that sentence reads as a requirement and is
  reported against `requires-python`.
- **Django.** 294 of the 387 errors are `docs/internals/deprecation.txt`
  and `docs/releases/*` naming removed APIs (`django.utils.datetime_safe`,
  `django.utils.encoding.force_text()`) — accurate, and the reason release
  notes are excluded from the toolchain and staleness checks but not from
  symbol checks. The rest are the tutorial's `polls/` and `mysite/` project
  files (the reader's project, not Django's), `django.jQuery` (JavaScript)
  and `:ref:` labels defined in Python's documentation (`bltin-exceptions`,
  `logging-config-dictschema`), which intersphinx makes info. The first
  run reported 1,427 errors: `:doc:` targets got `.rst` instead of the
  tree's `.txt`, `/topics/x` targets were not climbed to `docs/`, template
  paths under `django/contrib/admin/templates/` were errors instead of
  "exists under" warnings, and `django.conf.urls.handler500` (a lowercase
  module-level assignment) was not indexed. Django's 64,000 symbols also
  exposed a quadratic corner: every unresolved name was scored against all
  of them; scoring only names of a compatible length took the run from
  14.6 s to 4 s.
- **pydantic** now reports 193 warnings instead of 10 errors for
  `docs/migration.md`: `pydantic.utils.to_camel` and friends exist in
  `pydantic.v1.utils`, and `pydantic/utils.py` is a shim that forwards to
  it, so "not found in module `pydantic.utils` (a `to_camel` exists at
  pydantic.v1.utils.to_camel)" is the honest verdict.
- **git cache.** With git, FastAPI's second run takes 1.9 s instead of
  14.8 s (1,692 blames and 3,000 logs answered from `git-cache.json`,
  240 KB); findings are identical.
